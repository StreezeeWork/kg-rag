# Постмортемы

## 1. Когда постмортем обязателен

Постмортем — письменный разбор инцидента, цель которого — найти системные причины и не допустить повторения. Постмортем обязателен в следующих случаях:

- для каждого инцидента уровня SEV1 и SEV2;
- для инцидента любого уровня, который длился более 4 часов;
- при потере или порче данных клиентов, даже если данные удалось восстановить;
- при двух откатах релиза одного сервиса подряд.

Для инцидентов SEV3 постмортем пишется по решению тимлида, для SEV4 достаточно записи в задаче «Орбиты».

## 2. Сроки и ответственные

Ответственный за постмортем — Incident Commander инцидента; он может делегировать написание инженеру, который глубже всех погрузился в проблему. Черновик постмортема публикуется не позднее 3 рабочих дней после закрытия инцидента. Финальная версия, согласованная с тимлидом, готовится не позднее 7 рабочих дней после закрытия. Для инцидентов SEV1 финальную версию дополнительно утверждает CTO.

## 3. Blameless-подход

Постмортем не ищет виноватых. Мы исходим из того, что каждый участник действовал разумно с учётом информации, которая была у него в тот момент. В тексте не указываются фамилии как причина сбоя: вместо «инженер Петров удалил таблицу» пишем «скрипт миграции позволил удалить таблицу без подтверждения». Главный вопрос — не «кто ошибся», а «что в системе позволило ошибке дойти до production». Для поиска корневой причины используется метод «5 почему». Наказание сотрудника за ошибку, честно описанную в постмортеме, запрещено.

## 4. Шаблон в «Атласе»

Постмортем создаётся в пространстве «Инциденты» вики «Атлас» по шаблону «Постмортем PM-3». Обязательные разделы шаблона:

1. Краткое описание: что произошло, уровень инцидента, длительность.
2. Влияние: число затронутых клиентов, доля неуспешных операций, финансовые потери в рублях.
3. Хронология с точностью до минуты: обнаружение, эскалация, смягчение, восстановление.
4. Корневая причина и способствующие факторы.
5. Что сработало хорошо и что помешало.
6. Корректирующие действия с владельцами и сроками.

Каждое корректирующее действие заводится задачей в «Орбите» с меткой postmortem. Для действий по инцидентам SEV1 срок выполнения — не более 30 календарных дней.

## 5. Разбор на встрече

Готовые постмортемы разбираются на еженедельной встрече «Разбор инцидентов» по средам в 16:00, встреча длится 45 минут. Встречу ведёт руководитель SRE-команды; участие автора постмортема и тимлидов затронутых сервисов обязательно, остальные инженеры подключаются по желанию. На встрече проверяют, действительно ли корректирующие действия устраняют корневую причину, и при необходимости назначают недостающие. Постмортемы SEV1 после разбора публикуются в канале #incidents в «Волне», чтобы выводы были доступны всем инженерам компании.

## 6. Контроль выполнения

Руководитель SRE-команды раз в месяц публикует в «Атласе» сводку по открытым корректирующим действиям всех команд. Просроченные задачи с меткой postmortem разбираются на той же еженедельной встрече вместе с тимлидом команды-владельца. Постмортем считается закрытым, только когда выполнены все корректирующие действия или для каждого невыполненного записано обоснованное решение отказаться от него.
